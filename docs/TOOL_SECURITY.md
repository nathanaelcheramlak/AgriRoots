# Tool execution boundary

Model output, remote descriptions, remote results and plugin manifests are untrusted data. They cannot grant permissions, select another office, approve a tool, choose a URL/header, run a command, follow a resource link or release an advisory. Only the administrator lifecycle and the fixed reviewed legacy handlers perform those respective operations.

The executor derives identity from the current active membership, validates the exact pinned operation and connection digest, checks the role and approval, resolves authorized plots, binds server-owned inputs, validates the full schema, checks egress data classes and explicit request authorization, then claims shared spending/concurrency counters. Each actual HTTP attempt rechecks permissions, cancellation, deadline, credential scope and worker lease. No connection with a modifying external effect can enter this path. Private-record transmission remains blocked. Image transfer is limited to the reviewed Kindwise handler, an office-owned server-bound asset, explicit credit authorization and a durable duplicate-submission receipt. Provider assessments can consume quota; no automatic repeat is permitted after an ambiguous result.

Credential values enter only the write-only connection API and are encrypted with Fernet before database storage. The key lives outside the database; previous keys can be configured for rotation. Decryption checks both office and connection ownership. API errors omit raw request input, provider bodies, tokens and secret-bearing URLs. A connection may not use the platform JWT signing secret, an app-issued login JWT, the Gemini key or the credential encryption key. The model receives no credential reference that it can use to fetch plaintext. Numeric model token-usage counts remain visible; secret fields and known credential values are redacted.

Every credential rotation changes its scope digest, suspends the connection and requires a fresh test and exact-version approval. This is deliberately stricter than a same-account rotation exemption. Old cache entries and pinned runs cannot inherit the new scope. Encryption-key backup/recovery and operator access to the ignored environment remain deployment responsibilities.

Egress permits exact operator-approved HTTPS hostnames on port 443. It rejects IP literals, private/metadata targets, credentials in URLs, query-bearing configured endpoints, path traversal, origin overrides and redirects. The application-owned authenticated CONNECT proxy validates the complete DNS answer set and opens a socket to a validated literal public address; TLS still validates the original hostname. Each SDK HTTP request uses that transport. Bounded decompression, wire-size limits, timeouts and request counters apply before large data reaches the model. Operator-only loopback fixture exceptions are rejected in production. No test sends an attack to an unrelated server; DNS/proxy tests use controlled resolvers and prevent the candidate external connection from being opened.

Production dispatch and administrator changes serialize on the integration row. A disable committed before the final gate prevents dispatch; already-started remote work cannot be recalled. Revocation after response arrival prevents its result from entering current evidence. PostgreSQL NOWAIT locks with async retry avoid blocking the event loop behind an in-flight request. SQLite cannot provide the same cross-process locking guarantee and is not supported for production. The supplied Compose stack uses a separate migration owner; the application role cannot update/delete approval/version bodies or audit events, or create public-schema objects. This is an application boundary, not database row-level security against a compromised service account.

Registry changes atomically bump a persistent office generation. New runs obtain fresh snapshots; runs retain exact selected versions. Permissions and emergency revocation remain database-authoritative even when Redis is unavailable or contains stale entries. Redis payloads are encrypted/authenticated and bind their partition key and expiry. Cache keys include office, tool/configuration version, credential scope/revision, authorized arguments and plot IDs. Cache hits preserve the original retrieval/validity provenance. A denied replay creates a separate audit record and does not overwrite the original terminal evidence.

Jobs use durable claims, expiring leases, heartbeats, bounded recovery attempts and stable invocation keys. A crashed worker may resume a checkpoint. Finished tool invocations can replay their recorded result after reauthorization; a previously dispatched invocation with an uncertain outcome returns `AMBIGUOUS_OUTCOME` and is not blindly sent again. Identical successful follow-up work in the same budget reuses its evidence. This is not a promise of exactly-once execution at an arbitrary remote API. Cancellation stops future dispatch but cannot reverse work already accepted by a provider.

Reviewing a remote tool's schema does not freeze its server implementation. Use trusted providers, least-privilege read credentials, data minimization and revocation. Generic read-only POST classification is an administrator-reviewed assertion; the application cannot prove an arbitrary remote server has no side effects. Costs remain unknown/null when a provider does not report them; configured request caps are not a dollar-spend guarantee. The release performs no automatic paid/diagnosis/startup probes. The legacy borrowed Fetch server is fixed operator infrastructure, not a tenant-installed process, and has a narrower fixed public-source proxy.

The default cloud policy accepts only synthetic plot contexts and rejects contact information in tasks. Raw household records are not sent to Gemini. Tool results remove exact coordinate/geometry/contact fields and URL queries before cloud use; full private source provenance stays in the authorized evidence store. Arbitrary free-form remote text can still contain sensitive material a provider returns; provider review and the synthetic-only boundary remain necessary. The implemented image path strips metadata, keeps bytes out of model context and transmits only to the reviewed diagnosis provider when authorized. Real-household cloud-model context remains subject to the deployment policy.
