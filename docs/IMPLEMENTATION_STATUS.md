The backend-only default demo persists configured objects via actual APIs, runs the actual graph with labeled HTTP/model fixtures, records evidence, and demonstrates revocation. `--live` explicitly authorizes the separate small public-provider checks. These are different reports and different forms of verification.

Deployable services are PostgreSQL, Redis, a single migration-owner job, API, connector worker and the existing four-tool internal HTTP MCP server. Hash-locked dependencies, non-root containers, a restricted application database role, explicit CORS, health routes and separate private storage are included. The internal HTTP test actually persists a review-only advisory draft; nothing is released to farmers automatically. The legacy Qwen worker/model runtime remains a separate optional workflow, documented by the original project guides.

Current limitations include: synthetic-only cloud plot contexts by default; no private-image transmission; no automatic advisory save/release tools in configurable companion skills; no universal scientific provider substitution/coverage ranking; no arbitrary user-defined parsers; no exact-once guarantee for remote services; no per-request visibility inside the fixed legacy third-party Fetch subprocess; and no dollar-cost estimates invented from token or request counts. Remote implementation changes remain a provider trust boundary even when schemas are unchanged.

Read `backend/reports/CONNECTOR_TEST_REPORT.md` for the final observed counts, acceptance matrix, live evidence, earlier failures and follow-up outcomes. `backend/reports/connector_test_results.json` is the machine-readable counterpart. Configuration samples contain placeholders; real credentials remain ignored. Set the Gemini key and an explicit supported model locally before authorizing a real model run.
